# Shark

Веб-приложение для QA: работа с задачами Jira, тестовая модель, планирование стендов, анализ логов и генерация тестовых событий.

## Возможности

| Раздел | Что доступно |
|---|---|
| Главная | Свободная сетка списков S/M/L/XL/XXL и квадратных счётчиков S, диаграммы, командная очередь, личные рабочие столы и активность сотрудников |
| Jira tool | Списки и папки задач, фильтрация, сортировка, EPIC/STORY, планирование, одиночное и массовое редактирование, регистрация дефектов (исполнитель SBER911 подставляется по компоненту и метке — `ASSIGNEE_RULES` в `jira_constants.py`), аудит списка и Excel всех представлений с листами дефектов |
| Тестовая модель | Генерация из «Данных», версий требований и нескольких макетов Pixso; планирование, проверка и XML для Zephyr |
| Zephyr Tool | Тест-кейсы (в «Все кейсы» — и архивные), массовая правка с предпросмотром (переписать / заполнить пустые / заменить), прогоны, релизы, импорт модели и критический регресс |
| График стендов | Общий план ИФТ/ПСИ из списков Jira tool, бронирование, конфликты, почасовая публикация в Confluence |
| Трекинг AQA | Jira, Bitbucket, Allure TestOps и Jenkins: роадмап, коммиты, запуски и результаты |
| Логи | Поиск через MCP по нескольким сервисам, загрузка текстовых логов до 500 МБ, фильтр ошибок, разбор ИИ и аудит |
| Тестовые данные | JDBC-подключения, просмотр схемы, поиск данных и генерация SQL |
| Генераторы событий | Алерты в Jupyter, Jobs, метрики, ТКС и генератор инцидентов. ИИ-помощник готовит отдельные черновики скриптов с параметрами запуска для вариантов сценария в требованиях Confluence или «Данных» |
| Просмотр Kafka | Подключения, топики и чтение снимка сообщений |
| Данные | Дерево требований, документы и QA-документация |
| Тестирование моделей LLM | Сравнение моделей на сценариях и экспорт отчёта |

«Главная» открывается после входа. Отдельные разделы «Автотестирование» и «Ревизор» скрыты; код сохранён.

Кнопка **Аудит** появляется рядом с уведомлениями, когда для активного раздела доступен журнал. В Jira tool это история выбранного списка. В «Логах» показываются запросы на анализ, а в «Алертах» администратору доступна история запусков ядер. При двух панелях журнал относится к панели, с которой пользователь взаимодействовал последней.

## Требования и запуск

- Python **3.10–3.12** для Shark.
- Node.js **20+** и npm.
- Java **17+** для JDBC-подключений; для остальных разделов не обязательна.
- SQLite либо PostgreSQL через `DATABASE_URL`.
- LLM и корпоративные интеграции настраиваются отдельно. Без них интерфейс запускается, соответствующие операции требуют подключения.

Из корня проекта:

```bash
bash install.sh
bash start.sh
```

Интерфейс: [localhost:3000](http://localhost:3000). API: [localhost:8000](http://localhost:8000), проверка запуска — [healthz](http://localhost:8000/healthz). Вход — логин и пароль Jira либо локальная универсальная учётка `Sber911` / `1234567` из `backend/api/auth.py`.

Для ручного запуска используйте два терминала с установленными зависимостями:

```bash
# Бэкенд: активное venv/Conda проекта
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

# Фронтенд: отдельный терминал
npm run dev --prefix frontend -- --hostname 127.0.0.1 --port 3000
```

Используйте один API worker: задания и сессии частично находятся в памяти. Сохранённые пользовательские настройки не заменяйте шаблонами при обновлении.

## Настройки и корпоративный запуск

Подключения редактируются в `/settings`. GigaChat поддерживает профили Личный, Corp и IFT; другие модели добавляются как chat/completions-compatible подключения. Для готовых пресетов (DeepSeek, Kimi, OpenAI и др.) достаточно вставить API-ключ. Kimi: ключ — platform.kimi.ai/console/api-keys, API — `https://api.moonshot.ai/v1`; модели K3 всегда рассуждают, поэтому Shark не передаёт им `temperature` и лимит токенов, а таймаут ответа — 10 минут. При `GIGACHAT_ONLY=1` сторонние провайдеры отключены.

[Инструкция корпоративного запуска](docs/gigacode-launch.md) содержит готовую просьбу ГигаКоду, порядок установки PVS, внешнюю конфигурацию, диагностику и приёмку. Шаблон — `config/corporate.env.example`. Проверка окружения без обращения в корпоративную сеть:

```bash
python scripts/shark_doctor.py --software-only
```

Для фонового запуска из сеанса ГигаКода используйте `bash scripts/restart.sh --with-gigacode` с настроенным `SHARK_ENV_FILE`. При обновлении из распакованной копии используйте [защищённое копирование кода](MIGRATION.md#обновление-установленного-shark-из-распакованной-копии).

Секреты и пути к сертификатам задавайте через окружение, внешний `SHARK_ENV_FILE` или предусмотренные UI-хранилища. `.env` и `frontend/.env.local` исторически отслеживаются Git; не добавляйте туда новые пароли, Cookie и ключи. TLS настраивается через доверенный CA и необходимые клиентские сертификаты.

Реальные PVS, Эфир, Jira и Confluence проверяются внутри корпоративной сети. Моки не подтверждают доступ и права.

## Требования и тестовая модель

- В «Данных» прикрепляйте исходники и ссылки на отдельные экраны Pixso. Версии содержания можно обозначать заголовками, строками `V2 — Доработка` или таблицей с колонкой «Версия» в исходнике либо на выбранной странице Confluence. «Обработать документ» собирает актуальный QA-обзор и дочерние страницы изменений. «Обновить документ QA» перечитывает тот же источник, сохраняет готовые страницы неизменившихся версий и обновляет затронутые разделы обзора. Предыдущая публикация доступна, пока идёт обновление.
- Схемы PlantUML в QA-документах отображаются встроенным рендерером на Node.js. При открытии ранее обработанного документа Shark автоматически строит схемы из сохранённого Markdown.
- Для планирования по задачам требуется хотя бы один непустой документ из «Данных». Его можно прикрепить в Jira tool или добавить в форме планирования. В форме доступны выбор сохранённой версии, произвольное уточнение и дополнительные ссылки на Confluence и Pixso. Путь фичи берётся из актуального дерева папок «Данных».
- В плане проверяйте отдельные строки для версий и комбинаций MCP-сервера и инструмента. Для связи микросервиса с КЭ используется [корпоративный справочник](https://confluence.sberbank.ru/pages/viewpage.action?pageId=25633370345). При недоступности используется локальная таблица. XML собирается из проверенных полей.
- Перед отправкой в Zephyr проверьте раскладку на дереве тестовой модели. Отметьте кейсы слева для общего переноса и перетащите их за ручку. При переносе видны исходная папка и подсвеченная папка назначения. Новую ветку можно перенести целиком. Кнопка «Переместить» позволяет выбрать путь без перетаскивания. Если убрать папку из черновика, её кейсы и вложенные папки поднимутся на уровень выше.

## Локальная демонстрация

Для демонстрации Jira, Confluence, Bitbucket, TestOps, Jenkins, LLM, PVS и Эфира используйте мок-режим:

```bash
SHARK_MOCK=1 python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Фронтенд запускается как обычно. JSON-данные и SQLite мока находятся в `data_mock/`; отдельный каталог задаётся `SHARK_DATA_DIR`. По умолчанию при первом запуске копируются локальные данные без сохранённых учёток PVS/Эфира. Это демонстрационный режим, а не изоляция всех сетевых подключений: Kafka, внешние JDBC-базы и произвольные скрипты не подменяются.

## Разработка

Backend: `backend/` (FastAPI), интеграции и генерация: `agents/`, хранилища: `db/`, frontend: `frontend/` (Next.js App Router, React, TypeScript, Tailwind). API-схема работающего бэкенда: [Swagger](http://localhost:8000/docs).

```bash
python -m pytest tests -q
npm run typecheck --prefix frontend
npm run build --prefix frontend
```
