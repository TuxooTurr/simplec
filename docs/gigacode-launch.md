# Передача ГигаКоду: запустить Shark в корпоративном контуре

Цель — подключить подготовленный проект к реальным PVS, Jira/Confluence и Эфиру. Главная, виджеты, командная очередь, редактор задач, справочник PVS и клиент Эфира реализованы и проверены на моках. Не заменяйте отсутствующие реальные доступы демонстрационными результатами.

## Что уже известно

| Ресурс | Параметры из материалов внутреннего контура от 20.11.2026 |
|---|---|
| PVS API | `https://tsles-sber00075.esrt.sber.ru:19200` |
| PVS веб для сверки | `https://tsles-sber00076.esrt.sber.ru:15601` |
| Namespace | `sber911-sigma-back` |
| Индексы | `sber-app-*` |
| Поля | `k8s.namespace.name.keyword`, `service.name.keyword`, `timestamp`, `level.keyword`, `message`, `mdc.traceId.keyword`, `stackTrace` |
| PVS MCP | Утверждённый `opensearch-mcp-server-py`, транспорт stdio, `SearchIndexTool(index, query_dsl, size[, format])` |
| Эфир MCP | `https://efir.sber.ru/api/platform/api/v1/mcp/mcp/`, Streamable HTTP, только чтение |
| Бэкенд | Python 3.10–3.12; у MCP отдельное окружение согласно его pyproject/lock |
| Фронтенд | Node.js 20+, `frontend/package-lock.json` |

Это исходные значения для проверки на хосте, а не подтверждение, что доступ уже выдан. PVS может не разрешать каталог индексов — для поиска достаточно явного индекса и mapping, доступ к каталогу не запрашивается как обязательный.

## Что получить только внутри контура

1. Утверждённый пакет PVS MCP из `InSourceHub_AI/AI_market/mcp/pvs-mcp`, его `pyproject.toml` и lock/версию. Публичную одноимённую сборку вместо него не устанавливать.
2. Корпоративную CA-цепочку, выданный клиентский сертификат PVS и соответствующий приватный ключ. На ИФТ требуется mTLS. Файлы остаются на хосте, ключ — с ограниченными правами.
3. Действующие учётные данные PVS с правами поиска/агрегации в нужном namespace. Пароль через хранилище секретов или UI PVS; в Git, чат и отчёт его не помещать.
4. Корпоративный SSO/сертификат для входа в Эфир либо разрешённую серверную сессию. Короткоживущую Cookie получать на хосте через кнопку подключения; не пересылать наружу.
5. Подтверждение доступности DNS/маршрутов/прокси и пакетных зеркал. Разрешённые версии браузера и способ запуска GUI на целевом компьютере.
6. Живой `tools/list` обоих MCP и фактические формы ответов. Проверить реальные параметры поиска, агрегации сервисов, `peer`, пагинацию и даты Эфира. Сырые логи и переписку не выносить из контура; для изменения адаптера достаточно обезличенного описания структуры.
7. Проверить действующие права Jira/Confluence, editmeta и переходы реальных задач, привязки страниц стендов. Проверки, изменяющие Jira, выполнять только на согласованных тестовых задачах.

Для строгой гарантии «ни одной пропущенной задачи» отдельно выяснить у администратора Jira: разрешены ли webhooks/журнал изменений, какие события доступны и как обеспечивается повтор доставки. Сейчас очередь надёжно сохраняет уже обнаруженные задачи; опрос сам по себе не гарантирует обнаружение кратковременного совпадения с произвольным JQL. Не объявлять эту гарантию выполненной без решения по событиям.

## Порядок запуска

1. Сохранить имеющиеся настройки и рабочие данные установки, особенно `data/dashboard.json`, базу настроек и ключ шифрования Shark. Не заменять пользовательскую `.env`, не удалять данные и не переключать действующий сервер на SHARK_MOCK.
2. Активировать окружение Python 3.10–3.12. Выполнить `python -m pip install -r requirements.txt` и `npm ci --prefix frontend` через разрешённые зеркала. Установить утверждённый PVS MCP в отдельное окружение по `docs/pvs-mcp.md`. Playwright использует установленный Сбербраузер/Chrome; браузеры из интернета скачивать не требуется.
3. Создать закрытый локальный файл дополнений:

```bash
python scripts/shark_doctor.py --init-env "$HOME/.simpletest/shark-corp.env"
```

Команда не перезаписывает существующий файл. В шаблоне уже есть адреса и mapping. Заполнить только `LOGS_MCP_COMMAND` и пути CA/cert/key, при необходимости namespace/индекс конкретной установки, браузер и редакторов Главной. Пароль PVS вводится в UI; Cookie Эфира получается входом в браузере. Для серверных секретов использовать окружение процесса/секрет CI.

4. Выполнить офлайн-проверку:

```bash
python scripts/shark_doctor.py --env-file "$HOME/.simpletest/shark-corp.env" --report .work/shark-readiness.json
```

По умолчанию сеть не используется. `missing` — исправить, `manual` — действие оператора. Проверяются окружение, зависимости, настройки, файлы сертификатов и соответствие пары; пароли, токены, пути к ключам и содержимое файлов не печатаются. `pass` для наличия файла/учётки не означает успешное подключение.

5. Запустить Shark с дополнением конфигурации:

```bash
SHARK_ENV_FILE="$HOME/.simpletest/shark-corp.env" bash start.sh
```

Дополнение загружается поверх базовой `.env`; сама `.env` не меняется. Бэкенд — один worker. Серверу нужен доступ к установленному MCP, файлам mTLS и хранилищу ключа шифрования. На машине без GUI Эфир подключается разрешённым `ETHER_MCP_HEADERS` из окружения.

6. В UI сохранить PVS-учётку, проверить подключение и «Обновить микросервисы из логов». Затем подключить Эфир кнопкой, выполнить SSO-вход и выбрать коллег для ленты.
7. На том же хосте выполнить живые проверки без вывода записей:

```bash
python scripts/shark_doctor.py --env-file "$HOME/.simpletest/shark-corp.env" --probe all --timeout 60 --contracts-dir .work/mcp-contracts-first --report .work/shark-live-readiness.json
```

Если учётки сохранены в UI, диагностику запускать с тем же `SHARK_DATA_DIR`, пользователем ОС и доступом к ключу шифрования, что у бэкенда. Для повторного экспорта выбрать новый каталог контрактов: старые файлы не перезаписываются. В отчёте нет логов, сообщений, авторизационных заголовков или секретов. Экспорт tools/list содержит структуру аргументов без description/default/examples; оставлять его внутри контура. При включённом SHARK_MOCK живая проверка отвергается.

## Приёмка

- Главная открывается первой, доступна команде, настройки меняет разрешённый редактор. JQL и период произвольные; карточка, фильтры/сортировка, кольцевая и столбчатая диаграмма работают на реальных задачах.
- На тестовом счётчике обработка/отмена одной или нескольких задач видна второму пользователю и сохраняется после перезапуска. При ошибке Jira показывается ошибка и последняя выдача, а не ложный ноль.
- Изменить исполнителя/поле у одной и нескольких согласованных тестовых задач; проверить результат в Jira. Поле вне editmeta не отправляется; ошибка одной задачи видна отдельно. Не использовать массовую запись как тест на реальных производственных задачах.
- PVS: выбрать известную операцию и её временное окно; сравнить service/time/level/message с веб-интерфейсом. Проверить один сервис, все сервисы, ошибки, справочник и trace-переход. Пустое окно без известной операции не доказывает корректность mapping.
- Эфир: проверить все три вкладки «Чат / Почта / Встречи» через один MCP и одну сессию. Сверить readOnlyHint, инструменты/аргументы почты и встреч, даты и участников; при необходимости задать ETHER_MAIL_TOOL / ETHER_MEETINGS_TOOL и адаптировать контракт. Проверить отдельные фильтры коллег/слов, подсветку, скрытую конфиденциальность и повторный вход после истечения сессии. Недоступность канала не считать успешной пустой выдачей. Отправки сообщений нет.
- Если настроена публикация стендов, проверить обе привязанные страницы Confluence и часовой запуск, сохранив существующие права страниц.
- Локальные проверки: `python -m pytest tests/test_dashboard.py tests/test_jira_edit.py tests/test_ether.py tests/test_pvs_catalog.py tests/test_mcp_logs.py tests/test_stands.py -q`, `npm run typecheck --prefix frontend`, `npm run build --prefix frontend`. Полный набор запускается `python -m pytest -q`; прежняя заглушка теста Zephyr приведена к действующему контракту `timeout`, логика продукта Zephyr не менялась.

Зафиксировать версию установленного PVS MCP, успехи/ошибки приёмки, выполненные изменения контракта и оставшиеся блокеры. Не писать «готово», если доступны только моки или не выполнен реальный поиск/вход.

## Готовая просьба ГигаКоду

> Прочитай `AGENTS.md`, `README.md` и `docs/gigacode-launch.md`. Подготовленная версия Shark уже реализует Главную, командную очередь, общий редактор Jira, PVS и Эфир. Выполни корпоративную часть инструкции: сохрани настройки и данные; получи утверждённый PVS MCP из AI-market, сертификаты/секреты только на хосте; установи зависимости; заполни локальный SHARK_ENV_FILE; запусти shark_doctor сначала офлайн, затем с явным --probe; подключи Эфир через SSO; сверь живые tools/list и при необходимости адаптируй только контракт. Пройди приёмку на согласованных тестовых задачах, проверь сохранность общей очереди. Не считай моки подтверждением корпоративной работы, не отправляй наружу логи, переписку, Cookie, пароли и ключи. Верни краткий отчёт: что запущено, что проверено на реальных источниках, какие доступы/данные ещё нужны. Не переписывай готовые модули без найденного расхождения.
