# График стендов ИФТ и ПСИ

ИФТ соответствует Major-Check, ПСИ — Major-GO. Отдельного стенда ПРОМ нет.

## Как заполнить план

1. В любом сохранённом списке Jira tool добавьте задачу в папку и заполните «Микросервисы».
2. В карточке задачи укажите «Передача на стенд ИФТ» и/или «Передача на стенд ПСИ».
3. Заполните плановое окончание задачи Jira. Оно задаёт конец периода; дата передачи — начало.

Папка автоматически становится строкой команды на графике. Все списки, включая архивные, объединяются. Одинаковые задача, папка и микросервис дают одну полосу. Для задач без папки используется «Без папки». Без планового окончания полоса не строится; название папки уже видно. Даты передачи хранятся в Shark и не записываются в Jira.

Будущие рабочие дни доступны после окончания настроенного окна. Прошедшие дни доступны для просмотра. Ручные брони сохраняют правила выходных, заморозок и лимита. Масштаб меняется кнопками и Ctrl/Cmd + колесо, горизонтальная прокрутка — перетаскиванием.

## Публикация в Confluence

Настройте подключение Confluence и выберите страницу каждого стенда в разделе графика. Учётной записи нужны чтение страницы и её свойств, изменение страницы и запись свойств. Публикация использует существующие права страницы; права доступа читателям настраиваются в Confluence.

Основная таблица для читателей содержит папку/команду, микросервис, ключ задачи, фичу, начало и окончание, источник и состояние. Одна строка описывает один период. Конфликты между командами выделены красным. Подробный календарь и таблица по дням находятся в раскрываемом блоке. Заявки по-прежнему можно оставлять комментариями по шаблону на странице; их забирают отдельной кнопкой в Shark.

Публикация обеих привязанных страниц выполняется:

- каждый час при работающем бэкенде;
- по иконке обновления в шапке окна графика.

Повторное нажатие во время публикации присоединяется к текущему запуску. Обновление Jira и Confluence выполняется фоном, поэтому длительная выгрузка не держит открытый HTTP-запрос. Статус, последнее успешное обновление и ошибки показаны под сводкой графика. Отсутствующая привязка одного стенда не мешает другому.

Перед первым закрытием браузера откройте обновлённый Shark: после входа приложение сохранит серверный снимок состава всех списков. Последующие изменения списков, папок, микросервисов и дат передачи отправляются автоматически. После этого браузер можно закрыть — сервер использует сохранённый снимок и каждый час заново читает плановое окончание из Jira. Снимок содержит данные планирования, а не весь список и его колонки. Локальные изменения, не успевшие попасть на сервер при недоступном подключении, будут повторно отправлены после восстановления связи и открытия приложения.

При ошибке Jira используются последние известные даты с предупреждением. Если даты ещё не получены, период задачи не публикуется. Ошибки одной страницы не останавливают вторую. Кнопка обновления позволяет повторить попытку сразу.

## Сопровождение

- Планировщик `agents/stand_sync.py` запускается/останавливается в lifespan FastAPI. Поддерживаемый запуск приложения — один worker, как и для остальных фоновых задач проекта.
- Снимки, кеш дат и состояние публикации хранятся в `metrics_settings`: `stands_jira_plan_sources`, `stands_jira_plan_issues`, `stands_publish_status`. При переносе установки переносите БД настроек вместе с подключениями.
- Сохраняемые источники различаются по идентификатору браузера; одинаковый ID списка берётся из его последнего снимка. Отдельные списки разных источников объединяются, совпадающие полосы исключаются.
- API: `PUT /api/stands/plan`, `POST /api/stands/sync` (202), `GET /api/stands/sync-status`. Все требуют обычной авторизации Shark.
- Ручные брони остаются в свойстве Confluence `simpletest-stand`. Полосы Jira tool подмешиваются при чтении и публикации, не копируются в это свойство. Версионные конфликты Confluence повторяются с перечитыванием актуальных данных.
- Проверки: `python -m pytest tests/test_stands.py tests/test_jira_tool.py -q`; `npm run typecheck --prefix frontend`.
